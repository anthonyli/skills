# 金融风控系统术语表

本术语表适用于用户当前上下文中的金融反欺诈 / 风控系统：天策决策引擎 + 极溯指标平台 + 前端仓库映射。

## 一、系统级术语

### 金融风控系统
面向银行、支付、信贷、交易、账户安全、商户管理等场景的风险识别和处置系统。典型链路是：业务事件进入系统 → 字段标准化 → 指标计算 → 规则 / 模型 / 名单 / 评分卡 / 函数判断 → 策略输出风险决策 → 日志、分析、测试、回测闭环。

### 反欺诈系统
金融风控系统中偏“欺诈识别”的部分，关注账户盗用、电信诈骗、异常登录、交易欺诈、商户欺诈、套现、洗钱、钓鱼等风险。通常更依赖实时指标、设备 / IP / 账户 / 交易行为规则、名单、三方数据和模型评分。

### 极溯指标平台
指标 / 变量 / 特征生产和治理平台。负责字段管理、实时数据服务对接、离线数据接入、实时指标配置、离线指标配置、指标测试、指标上线、指标审核、实时指标初始化、离线指标调度计算、指标授权，以及向规则和模型提供指标结果。

### 天策决策引擎
风控策略执行与管理平台。负责策略、规则集、规则、决策流、模型、评分卡、函数、决策工具、名单、风险决策配置、测试、回测、批量决策、调用日志和效果分析。指标平台生产的指标会被决策引擎中的规则、模型、评分卡、函数和决策工具引用。

### 大盘
决策引擎中的监控分析入口，展示策略资产、规则命中、规则集命中、名单、策略效果、关联引用等信息。主要用于运营监控和策略效果观察，不是主要的策略配置入口。

### 系统驾驶舱
大盘下的总览能力，包含知识概览、系统大盘 / 决策历史、规则命中排行、规则集命中分析、关联引用查询、名单大盘、策略效果分析等。

### 知识概览
展示当前系统中策略、规则、函数、评分卡、模型、指标、三方服务、系统字段、机构、渠道、产品、注册服务等风控资产统计的页面。

### 系统大盘 / 决策历史
查看指定时间范围内策略调用、执行、命中、输出结果等历史记录的能力。常用于追踪某一笔业务事件的决策过程。

### 关联引用查询
查询策略、规则集、规则、指标、字段、函数、评分卡、模型、名单等配置项之间引用关系的能力。用于变更前影响分析，例如“这个指标被哪些规则引用”。

## 二、决策引擎核心术语

### 策略
针对具体业务场景配置的一套完整决策逻辑。策略可以由规则集、模型、评分卡、函数、三方服务、决策工具、子策略、判断节点和动作节点等组成，并输出通过、拒绝、人工审核、高风险、中风险、低风险等结果。

### 场景策略
面向具体业务事件的策略，例如登录策略、转账策略、交易策略、授信准入策略、放款策略、贷中预警策略、商户准入策略。通常和机构、渠道、事件类型、业务类型有关。

### 简易模式策略
由多个规则集组合而成的策略，规则集之间通常没有复杂的流程编排，执行效率高，常用于常规交易反欺诈场景。

### 流模式策略
通过流程画布编排的复杂策略。适合需要外部服务、模型、评分卡、函数、并行、判断分支、子策略、动作节点等复杂流程的场景。

### 决策流
流模式策略中的流程画布。节点可能包括开始、结束、判断、规则集、三方服务、函数、决策工具、模型、评分卡、冠军挑战者、动作、子策略、并行、继续补充、AI大模型等。

### 运行区
线上正在生效的策略、规则集、指标或其他资产区域。运行区变更会影响真实业务决策，通常需要上线、审核、发布等流程。

### 编辑区
配置、修改、测试、暂存资产的区域。编辑区修改不会直接影响线上运行，适合做策略、规则、指标的测试和版本准备。

### 策略版本
策略的版本化管理单元。用于支持复制、新增、导入、导出、单笔测试、批量测试、版本对比、发布上线、下线、回滚和发布历史查看。

### 普通发布
将某个策略版本直接作为线上生效版本发布。

### 分流发布
将多个策略版本按比例或条件分流执行，适合灰度发布、A/B 测试、冠军挑战者实验。

### 旁路发布
主版本照常产生真实决策，旁路版本只仿真运行并记录结果，不影响真实业务处置。适合观察新策略如果上线会产生多少拦截、误杀或漏放。

### 规则
由条件组合形成的判断逻辑。例如“近30分钟内累计失败交易次数 > 3 且发生转账，则拒绝”。规则可以引用字段、实时指标、离线指标、名单、模型输出、函数结果等。

### 规则集
多条规则的组合单元，用于对一个场景或交易形成局部决策。规则集常见执行模式包括首次匹配、最坏匹配和权重模式。

### 首次匹配
规则集按规则顺序执行，命中第一条规则后直接返回该规则的决策结果。适合强规则集合，例如黑名单命中直接拒绝。

### 最坏匹配
规则集执行所有规则，取命中规则中风险最高的结果作为规则集结果。适合多个风险等级规则同时存在的场景。

### 权重模式
规则集下每条规则有风险权重分，最终风险分为命中规则权重分之和，再映射到风险结果。适合综合评分型规则集。

### 规则模板
创建规则时可选择的预置逻辑模板。常见类型包括流程控制、时间规则、位置规则、统计规则、名单规则、设备规则、通用规则、高级规则等。

### IF规则
通过条件表达式判断是否命中，通常是最常见的规则形式。

### Terminate规则
流程控制类规则，命中后可终止当前规则集或流程继续执行。

### 条件规则
根据多个条件组合进行判断的高级规则，常用于复杂业务逻辑。

### 循环规则
对集合、列表或多项数据进行循环判断的高级规则。

### 脚本规则
通过脚本表达更复杂判断逻辑的规则，适合页面配置难以表达的条件。

### 规则添加到名单
规则命中后将某些实体自动写入名单，例如命中高危收款账户规则后写入黑名单账户。是“发现风险 → 沉淀名单 → 后续拦截”的闭环能力。

### 规则集引用变量
查看规则集引用的字段、实时指标、离线指标、离线图谱指标、外数指标等变量的能力。用于确认规则依赖和排查规则异常。

### 决策工具
用于结构化决策的组件，常见包括决策树、决策表、决策矩阵。可以引用字段或指标作为输入，并输出中间结果或决策结果。

### 决策树
按树形分支逐层判断条件并到达叶子结果的决策工具。

### 决策表
用表格行列维护条件组合和输出结果的决策工具。适合规则较多但结构规律的业务判断。

### 决策矩阵
用矩阵形式根据两个或多个维度交叉得出结果的决策工具，适合评级、风险等级映射等。

### 函数库
沉淀可复用计算逻辑的模块。函数可以在策略、规则、决策流中引用，入参可来自字段或指标，出参可参与后续判断。

### 评分卡
将变量分箱并赋分，最终汇总为分数、等级或结果的模型化组件。评分卡变量可以引用实时指标、离线指标、外数指标、字段等。

### 风险决策配置
维护系统最终可输出的风险结果，例如通过、拒绝、人工审核、高风险、中风险、低风险等。策略、规则集、评分卡、模型和动作节点可能引用这些配置。

### 决策调用记录
记录策略执行详情的日志模块。通常包含请求入参、策略版本、规则命中、指标查询、函数执行、模型调用、名单命中、三方服务调用、最终出参等。

### 公共规则库
沉淀可复用公共规则的模块。规则集可以引用公共规则库规则，减少重复配置并提升规则治理能力。

### 模型服务
管理和运行模型的模块。支持上传部署、版本更新、A/B 测试、权限管理、测试模型、上线模型、下线模型、结果对比、模型详情、下载和删除等。

### PMML模型
以 PMML 格式部署的模型，常用于标准化机器学习模型交换和在线评分。

### Python模型
以 Python 方式运行的模型，适合更灵活的特征处理和预测逻辑，但需要关注运行环境、依赖和性能。

### 数据预处理
模型管理中的脚本管理能力，用于模型输入前的字段转换、缺失值处理、特征加工等。

### 模型日志
记录模型操作和调用情况的模块，包括操作日志、调用日志、详情和过滤查询。

### 名单中心
维护黑名单、白名单、灰名单、设备名单、IP名单、商户名单、欺诈证据库等名单资产的模块。规则可以命中名单，也可以在命中后写入名单。

### 名单组
名单的组织分类单元，用于按业务或风险类别管理多个名单。

### 名单
具体的风险实体集合，例如黑名单手机号、黑名单身份证、黑名单银行卡、高危 IP、风险商户、欺诈收款账户等。

### 名单维度
名单匹配的实体字段维度，例如手机号、身份证、银行卡、设备ID、IP、商户号、地址等。

### 名单备注
名单数据的说明、标签或备注配置，用于沉淀原因、证据、来源、处置建议等。

### 名单审批配置
控制名单新增、修改、删除是否需要审批的配置。用于防止误加黑名单或误删风险实体。

### 名单共享
将名单资产授权或共享给其他机构 / 渠道 / 业务线使用的能力。

### 规则免疫
对特定对象、条件或场景豁免某些规则的能力。适合 VIP、测试账户、人工核实可信客户等例外处理。

### 策略免打扰
对特定对象、条件或场景减少或跳过策略干预的能力，常用于降低误杀和减少用户体验打扰。

### 策略实验室
策略和规则上线前后验证、回测、分析的模块集合，包含规则集测试、策略测试、规则集回测、策略回测、决策分析、分流旁路分析、数据集管理等。

### 规则集测试
对某个规则集输入样例数据，验证规则命中、输出、引用变量和执行逻辑是否符合预期。

### 策略测试
对某个策略版本进行单笔或批量测试，验证决策流、规则集、指标、模型、函数、三方服务和最终结果是否正确。

### 单笔测试
用一条请求数据测试规则、规则集或策略，适合定位单个案例的执行路径。

### 批量测试
用多条测试数据批量运行规则集或策略，适合上线前验证整体效果和异常数据覆盖。

### 回测
用历史数据重新运行规则集或策略，评估新策略或新规则如果应用在历史事件上会产生什么效果。回测准确性依赖历史指标值、历史字段、外数数据、模型版本等。

### 规则集回测
针对单个规则集的历史数据回放评估。

### 策略回测
针对完整策略版本的历史数据回放评估。可分信贷回测、交易回测等。

### 决策分析
对策略执行结果、规则命中、风险决策分布等进行分析的能力，用于观察策略效果。

### 分流旁路分析
分析分流发布或旁路发布产生的不同策略版本结果差异，用于灰度、挑战者策略和仿真策略效果评估。

### 数据集管理
维护单笔测试、批量测试、回测使用的数据集。可以通过文件导入、手动配置或 AI 智能生成方式生成数据集。

### 批量决策
离线或准实时批量执行策略的能力，适合存量客户风险评分、历史交易补跑、商户批量评级、贷中客户预警等。

## 三、指标平台核心术语

### 指标
在风控中也常叫变量或特征。它是基于原始字段和历史事件加工得到的可复用计算结果，例如近30分钟失败次数、近7天交易金额总和、设备近1小时关联账户数。

### 实时指标
基于流数据实时更新计算的指标。数据来源一般是线上业务数据，特点是响应快、时效性高、时间片粒度细。适合登录、注册、交易、支付等实时反欺诈场景。

### 离线指标
基于批数据离线调度计算的指标。数据来源一般是数仓 / Hive 等批数据，结果有一定延迟，但适合大数据量、大时间周期场景，例如近12个月逾期次数、近180天交易金额均值。

### 指标测试
用于快速验证指标逻辑是否正确，确保配置内容和业务理解一致，避免错误指标影响规则、模型或策略。

### 指标调度计算
通常指离线指标按调度任务进行批量计算，也可能在文档语境中关联实时指标初始化任务。排查时要结合“实时 / 离线”上下文判断。

### 指标逐笔计算
实时指标面向编辑区 / 运行区，基于历史事件逐笔计算历史时点的指标结果。常用于规则 / 策略回测和模型开发 / 训练。

### 指标初始化
实时指标上线后基于历史事件数据初始化中间分片，解决上线初期历史分片为空导致指标值偏低或为空的问题。

### 分片
实时指标存储中间数据的单位。实时窗口指标通常依赖历史分片计算。

### 主属性
指标计算或查询的主要维度字段，例如银行卡号、身份证、手机号、IP、设备ID。用于确定“以谁为中心统计”。

### 从属性
指标配置中的辅助维度字段。主属性 / 从属性本质上都是维度字段，具体选择通常不影响指标结果，但会影响统计维度、查询维度和配置表达。

### 包含当前笔
实时指标配置。计算指标时将当前这笔事件与历史分片融合后计算。例如第4次失败交易时，包含当前笔可能返回4。

### 不包含当前笔
实时指标配置。只计算当前事件之前的历史分片，当前这笔不参与计算。例如第4次失败交易时，不包含当前笔可能返回3。

### 取值非本字段
实时指标配置。正常情况下用当前字段值查询同字段维度的指标；取值非本字段表示用另一个字段的值去查询指标结果。典型场景是用“转入账户”的值查询“转出账户维度”的历史转出情况。

### 场景
指标平台服务决策引擎时的过滤维度，包括渠道、事件类型、策略等。用于控制哪些渠道、事件或策略产生的数据可以更新该指标。

### 系统字段
将业务原始字段标准化后的字段。指标配置、规则配置和模型入参通常引用系统字段，而不是直接引用原始报文字段。

### 动态字段
基于已有字段或事件上下文计算出的派生字段，例如事件发生小时、金额是否能被10整除。指标使用动态字段时，需要在机构对接服务中同步配置，否则指标可能取不到数据。

### 字段映射
实时数据服务对接中，将业务数据原始字段映射为系统字段的配置。指标异常时必须检查字段映射是否正确。

### 实时数据服务对接
配置实时接口服务的入参、出参、原始字段与系统字段映射关系，为实时指标和决策调用提供数据基础。

### 离线数据接入
配置离线数据源、数据表和字段映射，为离线指标调度计算提供数据基础。

### 实时指标配置
配置实时指标基本信息、指标模板、主从属性、计算逻辑、过滤条件、高级配置等。

### 离线指标配置
配置离线指标基本信息、模板、计算逻辑、过滤条件和调度相关内容。通常不支持实时动态字段和实时场景筛选能力。

### 指标上线
将编辑区指标提交到线上可使用状态的动作。通常上线后还可能需要审核、初始化或调度。

### 指标审核
指标上线后的审批环节。若审批流开启，未审核通过的指标通常不能被规则或模型正式引用。

### 指标授权
将指标授权给对应机构 / 渠道 / 业务使用。规则或模型配置时通常只能看到已上线、已审核、已授权且权限匹配的指标。

### 规则、模型调用
指标上线、审核、授权后，可以被决策引擎中的规则、模型、评分卡、函数、决策工具等调用。

### 指标模板
指标平台中预置的计算模板，包括次数统计、求和、求平均、最小值、最大值、方差、标准差、关联个数、活跃天数、字段排行、移动距离、移动速度、历史取值、连续次数、连续累计、业务链、峰度系数、趋势、时间间隔、时间差、时间集中度等。

### 指标默认值
当满足条件的事件列表为空时，指标会按模板类型返回默认值。例如次数统计和关联个数通常为0，求和 / 均值 / 最大值 / 最小值等可能为null，布尔类可能为false。规则条件需要考虑默认值对命中的影响。

## 四、指标与决策的交叉术语

### 规则引用指标
规则条件中使用指标结果作为判断变量，例如“当前账户近30分钟失败次数 > 3”。该指标应来自指标平台，并满足上线、审核、授权、机构渠道匹配等条件。

### 指标作为模型特征
模型入参引用指标结果作为特征，例如交易欺诈概率模型使用近7天交易次数、近30天设备关联账户数等。

### 指标作为评分卡变量
评分卡分箱变量引用实时或离线指标，例如近12个月逾期次数、近90天交易金额均值。

### 指标作为函数入参
函数计算逻辑中使用指标结果作为输入，例如将多个指标组合成自定义风险分。

### 指标作为决策工具输入
决策树、决策表、决策矩阵使用指标作为条件维度或映射维度。

### 指标查询信息
决策调用详情中展示的指标查询记录，通常包括指标名称、指标标识、指标类型、指标值等，用于排查规则为什么命中或未命中。

### 历史指标值
回测时需要按历史时点还原的指标值。实时指标可能需要逐笔计算或铺底，离线指标需要历史调度结果，外数指标可能需要决定是否重新调用或跳过。
