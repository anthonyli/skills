# 常见排查清单

## 1. 规则里看不到某个指标

优先检查：

1. 指标是否已经配置完成。
2. 指标是否在正确区域：编辑区还是运行区。
3. 指标是否已上线。
4. 指标是否需要审核，审核是否通过。
5. 指标是否授权给当前机构 / 渠道 / 产品 / 业务线。
6. 当前规则、规则集、策略所属机构和渠道是否与指标权限匹配。
7. 指标类型是否符合当前组件支持范围：实时指标、离线指标、外数指标、图谱指标等。
8. 如果是动态字段相关指标，接口服务是否同步配置了动态字段。

常见结论：不是前端没加载，而是指标状态、审批、授权或机构渠道不匹配。

## 2. 规则配置成功但线上不命中

优先检查：

1. 规则状态是否启用。
2. 规则集是否上线，策略是否引用的是正确规则集版本。
3. 策略是否发布上线，线上是否执行到该策略版本。
4. 策略是普通发布、分流发布还是旁路发布。
5. 流模式中是否实际走到了该规则集节点。
6. 指标值是否符合预期，可在决策调用详情查看指标查询信息。
7. 实时指标是否包含当前笔，是否需要历史分片初始化。
8. 离线指标调度是否完成，是否存在延迟。
9. 字段映射、动态字段、数据类型、默认值是否正确。
10. 是否被规则免疫或策略免打扰豁免。

## 3. 新实时指标上线后规则命中偏低

优先检查：

1. 指标上线前历史分片是否为空。
2. 是否执行实时指标初始化。
3. 时间窗口是否很长，例如近7天、近30天。
4. 是否选择不包含当前笔导致当前事件未计入。
5. 场景过滤是否过窄，例如只允许某渠道、某事件类型更新。
6. 主属性 / 取值字段是否选错。

常见结论：实时指标上线初期没有历史分片，窗口指标需要初始化。

## 4. 回测结果和线上结果不一致

优先检查：

1. 回测策略版本是否与线上版本一致。
2. 历史指标值是否可还原。
3. 实时指标是否逐笔计算或铺底。
4. 离线指标是否使用历史调度结果，而不是当前最新值。
5. 外数服务是否重新调用、使用缓存或跳过。
6. 名单数据是否按历史时点还原，还是使用当前名单。
7. 模型版本、评分卡版本、函数版本是否一致。
8. 策略发布方式是否涉及分流或旁路。
9. 测试数据集字段是否完整，动态字段是否存在。

## 5. 策略导入后缺组件或无法上线

优先检查：

1. 目标环境是否存在同名 / 同标识系统字段。
2. 目标环境是否存在指标，并且类型、标识、机构、渠道匹配。
3. 目标环境是否存在风险决策配置。
4. 目标环境是否存在函数、模型、评分卡、决策工具、三方服务、名单维度等依赖。
5. 组件是否已上线并授权。
6. 导入策略中的版本引用是否能在目标环境解析。
7. 目标环境审批流是否阻塞上线。

## 6. 决策调用详情里指标值为空或默认值

优先检查：

1. 满足过滤条件的事件是否为空；不同模板会返回0、null或false。
2. 实时指标分片是否存在。
3. 离线指标调度结果是否生成。
4. 查询维度字段值是否为空。
5. 取值非本字段是否配置正确。
6. 字段类型是否匹配，例如数字、字符串、布尔、日期。
7. 场景过滤是否排除了当前渠道、事件类型或策略。
8. 当前笔是否被包含。

## 7. 不知道一个模块在哪个前端仓库

处理方式：

1. 先判断用户说的是业务模块还是技术组件。
2. 查 `frontend-module-map.md`。
3. 返回仓库、url 前缀、后端请求前缀。
4. 如果用户只说“决策”，结合上下文判断：
   - 天策决策引擎业务能力：可能跨交易、信贷、账户、决策中台组件。
   - 决策中台组件：`noah-react` / `noah` / `noahApi`。
   - 交易反欺诈：`spartan-react` / `trade` / `tradeApi`。
